# Only Us

A Flutter starter app organized by feature, with a Supabase service layer.

## Run

```sh
flutter pub get
flutter run
```

The app starts in preview mode when no Supabase keys are supplied. Sign-in,
registration, and live chat become available after Supabase is configured.

Pass the public Supabase project URL and anon key at launch:

```sh
flutter run \
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_PUBLISHABLE_KEY
```

For older projects you can use `SUPABASE_ANON_KEY` in place of
`SUPABASE_PUBLISHABLE_KEY`. Never put a Supabase secret or service-role key in
the app. Mobile clients are public clients; protect tables and storage using
Supabase Row Level Security (RLS).

Live chat expects a `messages` table with:

- `id` (primary key, generated by the database)
- `conversation_id` (text or UUID)
- `sender_id` (text or UUID, referencing the authenticated user)
- `content` (text)
- `created_at` (timestamp with time zone, defaulting to `now()`)

Enable the `messages` table for Supabase Realtime and configure Row Level
Security policies so only conversation participants can read and send messages.
The signed-in user enters their shared conversation ID in the chat screen.
Never ship a service-role key in the app.

## Message encryption helper

`EncryptionService` uses AES-256-GCM from the `cryptography` package. It
accepts a caller-provided 32-byte key and returns base64 data containing the
random nonce, ciphertext, and authentication tag. Decryption fails if the
ciphertext or key is invalid. This helper does not generate, store, exchange,
or rotate keys, and the chat service does not encrypt messages automatically.
Do not hard-code keys or treat this helper alone as an end-to-end encryption
design.

## Media and storage

Images can be selected from the gallery or camera for an on-device preview.
Uploading is provided separately by `StorageService`; create a private
Supabase Storage bucket and appropriate RLS policies before using it. Store
object paths rather than public URLs for private media, and request short-lived
signed URLs when displaying those objects. Camera selection requires the
platform permissions declared in the Android and iOS app manifests.
